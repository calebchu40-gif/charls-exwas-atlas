# Static atlas asset cache review (2026-10-23)

The public site serves its catalog JSON with GitHub Pages `Cache-Control: max-age=600` and an `ETag` (checked 2026-10-23 for `catalog.json?v=11` and `candidate_pair_explorer_v1.json?v=1`). The frontend previously used Fetch `cache: no-store` for every JSON request, which bypassed the browser's reusable HTTP cache on every visit.

Updated JSON fetches to `cache: no-cache`: the browser revalidates with the server and may reuse a matching cached representation after a `304 Not Modified`; changed responses are fetched normally. This preserves freshness while avoiding repeat transfer of unchanged assets. The public `catalog.json` is about 23 MB uncompressed and `candidate_pair_explorer_v1.json` about 6.3 MB; other topic catalogs add several more MB. A follow-up page-load review found that hidden topic views also fetched their JSON eagerly. All 21 topic catalogs now load only when their matching navigation view is opened; the 23.3 MB main field catalog loads only when opening E/P/C/group views, and the 6.3 MB pair index loads only when opening candidate-pair search. The default overview now downloads no JSON catalog at startup. The 23 JSON assets actively requested by the app total 34.0 MB uncompressed, and all load only after the user opens the corresponding view; 29.6 MB of that total is the two large indexes. Seven additional JSON files are included in the static directory but are not fetched by the app. This reduces first-view transfer and parse work while loading each directory on demand. The app script URL was version-bumped so browsers fetch the revised loader.

Validation: the isolated deferred-loader test confirms no fetch occurs before view entry and repeated entry issues only one request; all 21 mapped topic views and status elements exist; 70 Python tests and `node --check site-prototype/dist/app.js` pass. Checked deployed response headers for ETag and max-age. Post-deployment verification should confirm `app.js?v=57` is served, the overview does not request JSON catalogs, entering a topic requests its JSON once, and revisiting it reuses the cached representation. This change does not affect catalog contents, the analysis state, or CHARLS data.
