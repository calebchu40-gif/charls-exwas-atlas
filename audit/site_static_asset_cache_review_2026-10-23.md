# Static atlas asset cache review (2026-10-23)

GitHub Pages responds for static JSON with `Cache-Control: max-age=600` and an `ETag`. On 2026-10-23 this was checked on the then-published `catalog.json?v=11` and `candidate_pair_explorer_v1.json?v=1`. The old frontend used Fetch `cache: no-store`, forcing browsers to bypass reusable cached representations. The frontend now uses `cache: no-cache`, which revalidates with ETags and can reuse unchanged files after a `304 Not Modified`.

A page-load review found that every hidden-view directory was also fetched at startup. All 21 topic catalogs now load only after the matching view opens. The default overview requests no catalog JSON. Candidate-pair search loads its 6.28 MB index only when opened.

The 23.3 MB master field catalog is split by role for browser use: E is 15.46 MB, P is 6.40 MB, and C is 1.93 MB uncompressed. The frontend loads only the selected role shard. The shared `catalog.json` remains in the source repository for builds and audits, while the Pages deployment workflow removes it from the published artifact. The 25 JSON files that the app may request sum to 34.50 MB uncompressed, but each is fetched only when its matching directory is opened. Seven other JSON files in the source `dist` folder are not requested by the app.

The role shards are generated by `scripts/site_catalog_shards.py` during both full and finalize-only metadata builds. Tests compare each generated file with the exact role-filtered master and check that dual-role rows appear in both relevant shards. The app loader test confirms a topic file is not fetched before view entry and that repeated entry triggers only one request.

Validation: `python scripts/build_ep_atlas_metadata.py --finalize-only` completed; 73 Python tests passed; `node tests/test_deferred_asset_loader.cjs` passed; `node --check site-prototype/dist/app.js` and `git diff --check` passed.
