# CHARLS 全暴露—表型扫描方案 v1（待批准，尚未运行）

日期：2026-11-02
状态：**计划与调研稿**。在尺度、校正与披露规则签字确认前，不运行全量扫描。
范围：同一波次内所有可配对的暴露—表型组合（不做"同单位子集"方案 B）。

---

## 0. 一句话结论

CHARLS 能做的是"同一波次、同一次访谈/体检内"的横断面 E×P 扫描；**统一尺度靠三件事**：
①暴露按波内 z-score（必要时先 log10）；②表型按波内 z-score / 二分类 OR；③所有结果统一报"每 1 SD"
或"OR"并给出 q 值。跨波只在同名同单位时合并。

## 1. 参考方法（两家知识图谱怎么做）

### 1.1 NHANES Phenome–Exposome Atlas

来源：<https://pe.exposomeatlas.com/>；代码 <https://github.com/chiragjp/nhanespewas>

| 环节 | 原文/代码事实 |
|---|---|
| 规模 | 619 暴露 × 305 表型 × 10 个 NHANES 波次，**>100,000 条关联** |
| 暴露变换 | `log10_xform_variable()`：右偏变量取 log10；零值用最小正值的平方根替换 |
| 标准化 | `scale_e=TRUE`（暴露 z-score）、`scale_p=T`（表型标准化）→ 效应为"每 1 SD" |
| 类型识别 | `check_e_data_type()`：连续 / continuous-rank / 分类，三套建模路径 |
| 协变量 | `adjustment_models`：9 套场景（base、年龄、+性别、+收入教育、+族裔…）→ 页面上的 **Specification Bias** |
| 多重校正 | **FDR < 5%** 才展示 |
| 跨波合并 | `stanley_meta()`：Stanley 加权最小二乘，报 I²、Q、Stouffer p；而非简单 DL |
| 页面 | 表型页 6 个标签：`-log(P) vs 暴露组`、`Effect Sizes`、`R²`、`-log(P) vs Effect Size`、`Globe`、`Specification Bias` |

### 1.2 GutBiomeDB

来源：<https://gutbiomedb.online>；<https://github.com/zhai199887/GutBiomeDB>

| 环节 | 做法 |
|---|---|
| 原始值 | 相对丰度（%），各研究内部归一化 |
| 单研究 | 差异分析产出效应量（log fold change / SMD / OR） |
| 跨研究 | **DerSimonian–Laird 随机效应**合并，报 I² |
| 展示 | 全球地图、年龄组堆叠、Top20 条形、属丰度条形、门→属 Sankey |

### 1.3 共同规律（本方案的依据）

```
原始单位（μg/dL、cm、yes/no、%）
   → 变换（右偏取 log）+ 波内/研究内标准化
   → 通用尺度（每 1 SD / 每翻倍 / OR）
   → 统一模型 + 抽样设计 + FDR
   → 跨波/跨研究合并（I²、方向一致性）
```

**结论：能统一的是"效应量尺度"，不是原始单位。** 因此 CHARLS 的全部结果都应换算成
"每 1 SD（连续暴露）"或"OR（分类暴露）"再比较。

## 3. 统一尺度方案（核心）

### 3.1 暴露侧

| 暴露类型 | 变换 | 报告尺度 | 示例 |
|---|---|---|---|
| 连续浓度（血检） | 偏度 > 1 → log10（零值按 PE Atlas 规则替换）；波内 z-score（加权均值/SD） | **每 1 SD（log10 后）** | 血尿酸、HDL、CRP |
| 连续问卷量（年龄、收入、时长、BMI） | 不取对数，波内 z-score | **每 1 SD** | 睡眠小时、收入、BMI |
| 有序分类（燃料清洁度、频率） | 保留等级，线性项 + 哑变量 | **每 1 级** 或 OR | 炊事燃料等级 |
| 名义分类（燃料类型、水源、教育） | 哑变量 vs 参照组 | **OR** | 煤 vs 电 |
| 二分类 | 0/1 | **OR** | 自来水入户 yes/no |

稳健性替代尺度（只在主结果显著时补报）：**每 IQR**、**每翻倍**（log2 单位）。

### 3.2 表型侧

| 表型类型 | 模型 | 报告尺度 |
|---|---|---|
| 连续（血检、体测、血压、肺功能、握力、认知分、CES-D） | 加权线性回归 | **标准化 β（每 1 SD）** |
| 二分类（医生诊断、ADL 受限、自评差） | 加权 logistic | **OR** |
| 有序（自评健康 5 级、睡眠分级） | 有序 logistic | **OR/级** |
| 计数（慢病数、ADL 项数） | Poisson / 负二项 | **RR** |

### 3.3 模型与设计

| 模型 | 协变量 |
|---|---|
| **主模型 M1** | 年龄、年龄²、性别、教育（3 哑变量）、收入五分位、城乡；血检结局另加空腹状态 |
| 最小模型 M0 | 年龄、年龄²、性别 |
| 完全模型 M2 | M1 + 吸烟、饮酒、BMI（**仅敏感性**，避免中介调整） |

设计：官方权重 + `communityID` PSU + 分层 WR Taylor（与现有 950 条同一引擎）。

### 3.4 多重校正

| 层级 | 规则 |
|---|---|
| **主口径** | BH-FDR，家族 = **波次 × 结局域**（血液/体测/血压/肺/肌力/认知/心理/慢病/功能） |
| 同时报告 | 全站 BH-FDR、家族内 Bonferroni |
| 输出字段 | `p`、`q_family`、`q_global`、`k_family`、`n_model` |

理由：全站 18 万次检验直接用单一 FDR 会把真实信号压掉；分域家族既可控又可解释。

### 3.5 跨波合并（第二阶段）

- 仅当**同名、同单位、同检测方法**时合并；DL 为主，Stanley WLS 为敏感性。
- 报 I²、τ²、方向一致率；单位不同先按官方换算（如 mg/dL ↔ mmol/L）并记录在元数据。
- 无法换算（如 2011/2015 检测体系差异）→ **不合并**，只并列展示。

## 4. 暴露与结局的纳入 / 排除规则

### 4.1 纳入（可做）

**暴露**
- 家庭环境：炊事燃料、取暖能源、自来水、住房结构、资产指数
- 行为：吸烟、饮酒、睡眠时长、体力活动
- 社会经济：教育、收入、医保、工作状态
- 体测/血检（作为暴露）：BMI、腰围、血压、血糖、血脂、尿酸、CRP
- 社区问卷（**标记为 area-level**，与个体暴露分开）

**表型**
- 血检 17–18 项（2011/2015）
- 体测 15 项（2011/2013/2015）
- 血压、肺功能、握力、步行、椅子起立
- 认知（词表回忆、连续减 7）、CES-D
- 自评健康、睡眠
- 医生诊断（二分类，约 16 项）
- ADL/IADL、功能受限

### 4.2 排除（做不了，直接舍弃）

| 项 | 理由 |
|---|---|
| 2020 家庭暴露 | 编码与 2011 不一致，无数值映射 |
| 2018 血检 | 该波无静脉血 |
| 2013 血检 | 该波无静脉血 |
| 2014 生命历程 | 特殊回顾调查，单独目录 |
| 2020 COVID 模块 | 回顾性、时间窗不同，单独处理 |
| 药物/疫苗/器械条目 | C 类元数据，非暴露 |
| 单位不明且分类数 > 6 的无序变量 | 无法标准化 |
| 缺失 > 30% 的字段 | 完整案例过少，偏倚大 |
| 常量或近似常量（SD=0、>99% 同值） | 无变异 |
| 结局事件 < 50 或患病率 < 2% | OR 不稳定、披露风险 |
| 身高/体重作为"结局"且同时做暴露 | 循环；按方向分别建模 |

## 5. 规模测算

按目录字段数（已扣除约 45–50% 的质量过滤）估算主模型数量：

| 波次 | 连续暴露 | 分类暴露 | 连续表型 | 估算模型数 |
|---|---|---|---|---|
| 2011 | 463 | 241 | 68 | 63,400 |
| 2013 | 300 | 142 | 56 | 34,900 |
| 2015 | 271 | 164 | 69 | 40,000 |
| 2018 | 317 | 284 | 40 | 37,300 |
| 2020 | 66 | 72 | 5 | 3,800 |
| **合计** | | | | **≈ 17.9 万** |

- 加 2 套敏感性模型 → **约 53.8 万次拟合**
- 运行时间：按 0.25 秒/模型、8 并行 → 主模型 **≈1.6 小时**，含敏感性 **≈4.7 小时**；
  加数据准备与写库，**预留 8–12 小时**
- 存储：每条结果约 0.5 KB → 主模型 **≈90 MB**，全量 **≈270 MB**（私有库）

> 上述是**上限估计**；真实可估模型数会因完整案例、共线、稀有结局进一步下降。

## 6. 工程与验证

1. **数据冻结**：每波次生成分析宽表（暴露 + 表型 + 协变量 + 权重 + PSU），记录哈希。
2. **并行**：按"波次 × 结局"切片，8–16 进程，断点续跑；每片写 JSONL。
3. **一致性校验**：把现有 950 条中同模型同变量重跑 100 条，要求估计值误差 < 1e-6。
4. **质量门**：每次拟合检查 n、事件数、权重和、PSU 数；失败记录原因而非静默丢弃。
5. **入库**：SQLite（私有）→ 生成公开聚合（汇总 + Top 命中 + 显著 CSV）。
