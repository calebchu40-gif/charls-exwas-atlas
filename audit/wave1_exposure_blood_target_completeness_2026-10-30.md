# Wave 1 家庭环境—血检候选覆盖审计

**日期：**2026-10-30（Asia/Shanghai）
**状态：**受控元数据/候选资格诊断；不是关联分析或模型放行

## 目的

在投入正式试点计算前，检查已登记的家庭环境暴露在官方 Wave 1 Blood 目标记录中是否具有预设对比类别支持，并检查 respondent spine 中的家庭字段拼接是否出现同户冲突。该步骤用于及早发现结构性空缺，不能替代抽样设计、权重、年龄域或方法审查。

## 数据范围与保护

程序在受保护的本机 CHARLS 工作区运行。它读取官方 Blood 文件中的 respondent ID 与 `bloodweight`，Wave 1 准备表中的 respondent ID、家庭 ID 及 `i016/i017/i019/i020/i021/i022` 六个登记字段，以及年龄派生候选表中的年龄区间和候选 domain 状态。没有读取任何血液表型值；不输出 ID、逐人行、精确计数或小单元结果。详细 QA JSON 保存在本机 `%LOCALAPPDATA%\CHARLS_ExWAS_Atlas\qa_outputs\`，不属于 Git 跟踪内容。

年龄区间表仍是未审阅候选。诊断只检查候选区间可用性，不将其用于筛选样本；年龄派生和抽样设计审阅标记仍为未通过。`bloodweight>0` 仅用于描述当前 Blood 文件目标框，不代表该权重已获准用于每个暴露—结局对比。

## 定性发现

- 六个登记环境字段的每个预设暴露/参考类别对比，在当前 Blood 目标框中都能找到两侧的候选记录。
- 在具有非缺失家庭键且暴露值可观测的记录中，没有发现同一家庭的该字段出现互相冲突的非缺失值。
- 供暖子域字段 `i021` 按问卷路由，仅在 `i020=2 (No)` 的候选子域中检查；不把跳题记录误认为暴露缺失。
- 仍存在未落入已登记对比代码、缺失/未解析候选年龄以及其他尚未审核的适用性问题。类别可见不等于字段值规则或完整案例资格已确认。

## 解释限制与下一步

这些结果只说明候选配对在结构上值得继续核验。它们不是最终模型样本量，不证明 `bloodweight` 对家庭暴露模块非应答的处理充分，不验证 45+ domain 的年龄算法，不恢复 Wave 1 的完整分层/PSU方差设计，也不证明历史105项试点有效。正式模型数仍为0。

下一步按顺序完成：

1. 独立审阅出生日期转换、年龄不确定区间及主/次目标域定义；
2. 完成 PSU、隐式分层及拆分社区问题的方差方法裁决；
3. 冻结每项暴露和结局的特殊码、有效值、单位、权重适用性、协变量角色及敏感性分析；
4. 通过来源、调查设计和方法门后，独立复核冻结试点并查看模型诊断，再决定是否扩展。

后续扩展依据估计可行性、样本支持、诊断和稳健性，不按 p 值显著性挑选配对。
