# NHANES PE Atlas 方法借鉴与 CHARLS 合规实现约定 v1

日期：2026-10-10。该约定适用于项目后续变量目录、派生、分析和网站代码。NHANES PE Atlas 论文与 `chiragjp/nhanespewas` 仓库提供工程组织和统计流程参考；CHARLS 官方用户协议、波次用户手册、问卷、代码本、发布说明和抽样设计说明决定 CHARLS 数据如何使用。

## 可复用的整体构建思路

1. **目录驱动而非散落硬编码**：维护概念目录和逐波 crosswalk，记录变量角色（可多角色）、原始字段、问句/测量、单位、类型、有效值/特殊码、覆盖、问卷路由、样本/权重范围、可比性与来源版本。NHANES 仓库以目录选取表型/暴露字段的结构值得借鉴；CHARLS 映射和键必须独立定义。
2. **先枚举配对、后估计模型**：先依据经代码本验证的有效取值生成逐波暴露—表型配对及样本流量，再对每对拟合波次内模型。清楚区分原始非空N、合法编码N、目标样本N、权重覆盖N和模型完整案例N。
3. **模型方案命名且可追溯**：借鉴 NHANES 的多层调整模型展示思路，但每个CHARLS候选模型须按估计目标、时序和因果图审查；营养、尿/血测量等只有在CHARLS实际存在且有方法依据时才做领域特异调整。
4. **转换由元数据明示**：为连续、二分类、有序、多分类、计数、检测限等定义变量专属转换、参考组和尺度；不根据变量名、整数外观或NHANES做法自动决定。模型输出保存效应值、标准误/区间、P/q值、分析N、权重/设计说明、转换、模型ID、软件版本和失败状态。
5. **多重检验与跨波复现先定义家族**：预先确定检验家族、校正方法、分析门槛、敏感性模型和波次重复性规则。CHARLS不同波次是同一纵向队列的重复观测；跨波汇总前要处理同一受访者的相关性，不能照搬独立 NHANES 周期的 meta-analysis。
6. **网站发布结果层而非微观数据层**：沿用可搜索变量目录和可筛选的关联结果界面。公开代码、变量元数据或汇总关联结果前，须符合 CHARLS 使用协议并审查稀疏单元/可识别风险；不得把 CHARLS 个体记录、可重建记录的接口或受限数据上传到网站/GitHub。

## 不得从 NHANES 移植的规则

- `SEQN`、NHANES 文件/周期映射、`SDMVPSU`/`SDMVSTRA`、`WTMEC2YR` 等权重字段或 NHANES 专用 merge 规则。
- NHANES 周期合并/权重除以周期数公式，成人/实验室子样本门槛，仓库中的 `n >= 500` 过滤值，以及 NHANES 变量代码、年龄范围和人群推断范围。
- NHANES 的实验室单位、检出限处理、分位点、参考组、样条/对数变换、完整病例规则或默认协变量集合；须由 CHARLS 逐波说明和变量定义独立支持。
- 把 CHARLS 五轮简单当作互相独立的调查周期，直接将横截面权重拼成面板权重，或将单波/子样本权重扩展到官方未说明覆盖的字段。

## CHARLS 专属硬约束

- 个人、家庭、社区模块分别按官方 ID/层级处理；每次连接都验证键唯一性、关系基数、匹配率和行数不变。问卷跳题、NEWIW/REIW、预加载、随机子样本、体检/血样资格都编码为显式路由状态，不能把结构性空值改成“否”。
- 个人记录只存本机非同步的受控目录。项目目录、GitHub、服务器或网页仅接收代码、公开说明和通过披露审查的聚合/模型结果；不以目录权限替代数据许可。
- 每一项权重要对应目标人群、调查轮次、模块/测量资格和官方非应答调整口径。方差设计字段不清楚时，报告限制并先暂停总体代表性解释，不臆造分层码或伪造权重。
- CHARLS 为纵向队列，波次间隔、刷新样本、访谈模式、问卷版本及实验室/体检模块变化均需显式记入概念可比性；仅在定义确实可比时才形成共同概念。
- 关键派生函数要有代码本边界检查、合成路由案例和聚合 QA；原始字段、转换、排除理由和来源版本须能从结果回溯。

## 当前代码检查与实施状态

截至本版，`scripts/` 中为目录构建、字段审计、候选状态派生和聚合配对覆盖脚本，尚无正式关联回归、NHANES survey design 或独立周期合并的生产代码。当前脚本搜索未发现 NHANES `SEQN`、`SDMV*`、`WTMEC*` 或 `n >= 500` 硬编码。现阶段不启动模型，直至逐波定义、变量类型/缺失、样本资格、适用权重和方差设计以及统计检验家族写入 CHARLS 配置。
