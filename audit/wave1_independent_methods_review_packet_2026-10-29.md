# Wave 1 设计与105项试点：独立方法审阅材料

**最后更新：2026-10-30**

**状态：当前审阅候选待独立调查抽样/生物统计审阅；未获模型运行或结果发布批准。**

**当前工作规格与审阅边界（2026-10-30）：**用户已确定 Option A：`communityID` 聚类、无未发布 strata、with-replacement Taylor 方差，必须标注为近似；这只是待审规格，不能宣称复现完整 CHARLS 分层多阶段设计。主分析候选为官方血检观察对象中年龄区间下界≥45的 domain；年龄上界≥45和完整观察血检框为预设敏感性。分析权重候选为 `bloodweight`。独立审阅人应评估该目标、近似设计、估计自由度、协变量、完整案例缺失与结局规则是否可接受；不再请审阅人替用户在 PSU 方案间做选择。本文后续与此段冲突的历史表述已按此处和下面的现行审阅矩阵更新。

**血液测量状态（2026-10-30）：**官方 Wave 1 `qc1_va003` 数值映射仍未找到。按最新项目决策，血糖和甘油三酯各7项已登记假设均保留在 K=240 家族内，但在取得权威编码、完成规则审阅前不可估计；其结果状态必须为 `blocked_measurement_rule`，估计与 p/q 为空。其余13项结局仍需逐项审阅有效域、特殊缺失值和变换；没有模型运行或发布批准。

本材料汇总当前可核实的方法信息及尚需决定的事项，供具备复杂抽样调查经验的审阅人评估。材料不含 CHARLS 参与者记录、样本计数、逐对结果或本地哈希。

## 当前可核实的证据

- 官方设计页面/用户手册将 Wave 1 说明为分层多阶段 PPS：县级单位按地区、城乡和 GDP 组织/抽取，再在每个县抽取3个社区；超过2,000户的大社区可拆分子社区作为最终 PSU，约30个社区采用了这一做法。选中45+主受访者后会访问其配偶，因此设计框内存在低于45岁的配偶；分析45+目标域需在设计对象中作 domain/subpopulation，而不能先物理删行。
- 官方用户手册说明 household/individual weights 来自各阶段抽样概率，并有非应答校正版本；血检另有校正血检非应答的 individual weight。对子社区抽样，权重还乘入子社区占父社区的份额。该权重支持目标点估计权重选择审阅，但不携带每位受访者所属最终子 PSU 的映射，不能单独解决方差估计。
- **受保护的血检权重连接复核（2026-10-30）：**按当前候选估计量，实际分析权重取 Blood 文件内的 `bloodweight`，不取主问卷 `ind_weight_ad2`。仅读取 ID/权重列的键值核对确认，Blood 发布记录的 `bloodweight` 均为非缺失正值，并全部链接到当前人口学个人主表；Blood 发布记录数与官方 Blood Guide 报告的完整血样数一致。因此，血检文件—生物标志物权重—个人主表的字段连接已通过。官方完整血检目标与个人主表之间仍有总体分母的小幅差异，且 `ind_weight_ad2` 存在未匹配 ID；该项保留为非血检权重分母的附属来源问题，不把它混同为 `bloodweight` 连接失败。此核对没有读取暴露或结局值，也不证明暴露模块应答覆盖、年龄域或方差设计正确。
- 设计是嵌套多阶段，而非单一社区聚类：官方文本先抽县级单位，再在县内以 PPS 抽社区；大社区可能继续抽子社区。已核发行 PSU 文件表头有 `communityID`、省/市名称、NBS 城乡/地区类型和版本字段，但没有明确标为县级抽样单元编码或方差层编码的列。受控 PSU 键拓扑 QA 确认省/市标签不能作为官方县级样本单位的一对一 crosswalk；精确聚合数和类别仅存本机 `%LOCALAPPDATA%\CHARLS_ExWAS_Atlas\qa_outputs\`，不公开。不得仅凭列名假定 county、strata 或 final PSU。
- 官方 2011 Codebook 的 PSU 节（印刷页 1340–1341）列出的变量为 `communityID`、`province`、`city`、`urban_nbs`、`areatype`，未列 county sample-unit ID 或方差 strata。该公开字段清单与实际 PSU 表头核验相符；release/version 字段是版本元数据，不构成抽样层变量。

- 用户确认 Wave 1 All Data、PSU、Weight、Blood 来自其获准 CHARLS 账号，对应官方数据项 123、117、118、201。服务器只读来源检查和准备表 provenance/hash 检查通过；该检查核对来源文件清单、Stata 表头和文件哈希，不读取受访者答案。
- 受保护发行包中15个 All Data 模块的字段名已经逐一检查。`sub_commuID` 只见于社区模块；其余14个模块均没有此字段。社区模块同时含 `communityID`。
- **键结构更正**：受保护复核发现社区模块的空白 `sub_commuID` 以空格存储。按空白规范化后，子区编号仅见于拆分父社区的多行记录；个体表只有父 `communityID`，不能据此分配这些父社区内的具体子 PSU。此前未处理空白的快速汇总会把空格误作有效值，已更正。完整候选处理矩阵见 [`wave1_variance_estimator_decision_matrix_2026-10-29.md`](wave1_variance_estimator_decision_matrix_2026-10-29.md)。
- 独立 PSU 文件的表头提供 `communityID`、省/市、NBS城乡、地区类型和版本字段；未见子 PSU 映射键、显式方差层或复制权重。社区字段存在不等于能确定个人所在子 PSU。
- Weight 文件含家庭/个人键及多类权重；Blood 文件含 `bloodweight`、空腹标记和15个常规血液分析物字段，另有 cystatin C。官方手册支持常规血液结局优先评估血检专用权重；cystatin C 因有年龄分层随机检测而暂不并入普通血检分析族。
- 受保护只读 `require_verified_wave1_frame` 检查通过；`require_wave1_analysis_readiness` 因没有绑定当前来源和方案的审阅记录而阻断模型执行。
- 两个 Wave 1 试点入口都在读取分析输入前调用上述来源与分析就绪门；当前没有审核记录时会 fail closed，不会进入拟合步骤。

## 105项方案候选（待重新冻结；以下不是已批准规格）

15项 Wave 1 普通血液结局的字段、原始单位、官方指南测定范围及尺度候选另列在 [`wave1_outcome_scale_readiness_2026-10-29.md`](wave1_outcome_scale_readiness_2026-10-29.md) 和 [`wave1_outcome_rule_cards_source_review_2026-10-30.md`](wave1_outcome_rule_cards_source_review_2026-10-30.md)。指南测定范围只是 assay metadata，不是可直接用于过滤的分析值上下限；15项结局尚无获批有效域或变换。

- 假设家族候选为 105 个系数：住所供水 `i017`（Yes vs No）15 项，加上烹饪燃料 `i022` 六个非电力类别分别对电力的 90 项；结局为 15 项常规 Wave 1 血液分析物，不含 cystatin C。官方燃料分类保持原样，不合并为“清洁/污染”。该方案是在早期水源探索后形成，须标记为探索性。
- 主要目标候选为官方血检观察对象中年龄区间下界≥45的 domain，保留完整观察血检设计对象并使用 `bloodweight`；上界≥45及全观察血检框作为预设敏感性。血检权重不能自动修正暴露、结局和协变量完整案例选择；该选择机制及推断范围须由审阅人判断。
- M0 仅用于描述；M1 主模型候选至少含暴露、官方来源年龄的非线性项、性别、教育和经核实的 NBS 社区城乡背景。M2 只增加有明确因果问题、时序清楚且非暴露后中介的预设敏感性变量。教育与城乡背景目前是核心混杂候选，不把它们默认降为仅敏感性。官方年龄区间的下界/上界/中点用途及不确定年龄处理均待冻结；不使用 Harmonized CHARLS D 年龄替代官方派生。协变量因果角色须与 [`core_covariate_readiness_2026-10-23.md`](core_covariate_readiness_2026-10-23.md) 的 DAG 审查共同冻结。
- `pilot105` 是嵌套执行批次，不单独形成 K=105 推断家族，也不计算 tranche q 值。主要推断须在预声明完整 K=240（K150+K90）全部完成后，按一次冻结的 primary-model 家族计算 BY-FDR 和 Bonferroni；14项测量规则阻断假设继续计入 K 但不获得虚构 p/q。敏感模型/变换若作为正式推断报告，须另行预先界定完整家族并校正。结果不能按显著性选配对；多重校正不能消除早期探索造成的选择性。
- 方差工作规格已由用户选定为 Option A：独立审阅应评估 `communityID` 单层 WR Taylor 近似的有效性、有限设计自由度、singleton处理和可支持的推断范围。公开资料未复原的县级 PPS/隐式分层/最终拆分社区 PSU 必须作为明确限制；如审阅认为 Option A 不可接受，应阻断关联推断，而不是自行换用未经核实的县码前缀或伪分层。
- 结局有效码、特殊码、单位/变换、LOD/顶码和 `qc1_va003` 空腹编码仍需逐项以官方材料审阅并在冻结前定版。指南测定范围不是默认清洗阈值；空腹编码未确认前，不据此筛血糖或甘油三酯样本。

## 新发现的测量条件问题：空腹状态

Wave 1 官方 Blood User Guide 说明采血前要求过夜空腹，但未空腹者仍采血并记录状态；指南指出非空腹血糖可能高于空腹测量。官方 Blood 文件含 `qc1_va003` 空腹字段。该字段在 Stata 文件中没有 value-label set；所取得的 Wave 1 Codebook 和 Blood User Guide 未给出数值编码。2015 的相近 `bl_fasting` 编码及第三方变量索引均不能用来解码 Wave 1。最新项目规则是血糖和甘油三酯各7项均保持登记但暂不可估计，直至权威 Wave 1 映射与测量规则审阅完成；具体证据见 [`wave1_fasting_code_source_review_2026-10-29.md`](wave1_fasting_code_source_review_2026-10-29.md)。

因此，任何真实模型运行前都必须核实 `qc1_va003` 数值编码，再由审阅人冻结血糖及甘油三酯的主估计、空腹域/协变量处理、敏感性及缺失标记规则。编码未核实期间两类结局的14项全部阻断；不可查看结果后再决定筛选方式，也不得按未经核实的编码划分 fasting/not fasting。此决定也会影响结局标准化参考域和估计目标。

**实现约束已核对：**scale-up runner 现要求血糖和甘油三酯为空腹限制或明确阻断；pilot105/full240 模板已将这两类结局设为 `blocked`，并禁止猜测代码。当前配置不批准拟合；今后若官方来源与审阅允许某种调整/敏感性，须先更新配置与校验器并重新绑定哈希，再进行合成软件校准。软件校准不等于 CHARLS 结果。

## 请审阅人决定的问题

1. 依据 CHARLS 分层、多阶段 PPS 与子社区拆分的真实结构，Option A（`communityID`、无 strata、WR Taylor）能否支持本项目限定的内部关联推断？其标准误、自由度、singleton处理及未建模阶段应怎样表述；如果不可接受，应否阻断关联推断？
2. 下界年龄区间≥45的血检 domain、上界≥45与全观察血检框敏感性是否与 `bloodweight` 目标及访谈/配对完整案例目标一致？
3. 对暴露—血检关联，年龄非线性项、性别、教育、NBS城乡背景的 DAG/因果角色是否合理？哪些变量可能是中介或暴露定义的一部分，不应调整？
4. `bloodweight` 是否足以支持暴露与协变量完整案例分析的目标推断？若不足，需何种事先定义的缺失处理或将结果限定为何种观察样本关联？
5. 除14项空腹相关阻断外，13项可候选结局的特殊码、有效域、单位、检测限/顶码和变换矩阵是否足够保守且可复现？
6. 依据 Guide 的预先分布描述，原始单位 identity 为主要候选、部分右偏分析物的 log 为敏感性候选是否适当？需满足哪些正值、解释尺度和多重检验条件？
7. 105项 pilot、K150/K90完整240项家族、可估性和披露规则是否满足可复现与可发布标准？

## 当前决策

在上述问题获得独立方法审阅并写入受保护审核记录、冻结的105项配置绑定到当前来源与代码之前，不拟合真实关联模型。用户已锁定的 Option A 和45+主 domain 候选仍须接受独立方法审阅，审阅人可以否决并阻断推断，但不应把它们误写成尚未由用户选择的事项。14项葡萄糖/甘油三酯假设继续留在预注册K=240家族中且无估计值/p/q。任何近似估计须明确说明遗漏设计阶段，不能表述为完整复现 CHARLS 分层多阶段设计或无条件全国代表性结果。没有任何结果可进入公开网站。
