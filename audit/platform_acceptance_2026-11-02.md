## 三、这一阶段修掉的问题（按严重度）

### 整页级（用户会以为网站坏了）

1. **标签条误用视图路由类** → 点任何标签整页空白。
2. **`loadConceptLabels` 在 app.js 与 modules.js 重复定义** → 关联页整页不可用。
3. **右上角「数据与方法说明」指向页内锚点却被当成视图** → 整页空白。
4. **手机端「更多」菜单锚定在横向滚动导航末端** → 菜单出现在屏幕外，6 个入口都点不到。

### 页面级

5. 目录表长概念 id 溢出到相邻列，文字重叠。
6. 目录表宽度 1,810px，最右侧的值标签列被裁掉。
7. 关联页热图面板被隐藏后无入口可打开（导航却叫「关联矩阵」）。
8. 移动端热图宽 2,972px，被面板直接裁掉（无滚动）。
9. 网络图左侧两个标签越出画布，首字被裁。
10. 「清除筛选 / 导出 CSV」在手机上错位堆叠。
11. 关联页 8 个筛选控件竖排超过一屏。
12. 目录只显示前 100 条且无翻页。
13. 首页占位卡（「纵向轨迹 · 即将上线」「API · 即将上线」）。
14. 打印时导航、筛选器全被印出，表格被滚动容器裁成一屏。

### 命名与一致性

15. 概念显示内部 id（`cooking_fuel_coal`、`blood_uric_acid`）而非中文 + 官方码。
16. 关联结果表、研究结果表仍显示原始 id。
17. 暴露组卡片标题为英文。
18. 慢病诊断页标题写 15 项，实际 16 项。
19. C 类元数据状态列整段英文。

### 工程与质量

20. 目录表行高被单个长字段撑到一屏。
21. 4 处浅灰文字低于 WCAG AA 对比度。
22. 253 个表头缺少 `scope` 语义。
23. 研究结果页 15 个标签无法分享（永远落在证据森林）。
24. GitHub 推送间歇失败（本机解析到的 IP 不可达，改为 `http.curloptResolve` 指定可用 IP）。

## 五、维护要点

- **新增页面**：先在 `index.html` 加 `<section class="view" id="...">`，再加 `data-view` 按钮；结构守卫测试会拒绝无视图的导航目标。
- **新增脚本**：必须带 `?v=N` 版本号，且文件存在于 `dist`；不得与其他脚本重名顶层函数或常量。
- **新增研究标签**：标签 id 必须与 `modules.js` 的 `active === '...'` 分支对应，否则守卫测试失败。
- **公开放数据**：必须同时通过 `validate_public_site_payload.py` 与 `validate_public_site_file_boundary.py`（后者要求文件在允许清单内）。
- **浏览器回归**：`node scripts/browser_regression.mjs [站点URL]`（需 CDP 9222 + 本地静态服务，CI 已内置该作业）
  覆盖 15 项：六入口、视图切换、方法锚点、标签条、中文标签、950 行结果、目录翻页、网络标签不出画布、
  手机菜单在视口内、无横向溢出、热图可滚动、**图表在手机上的有效字号 ≥ 9px**、**切换视图后焦点落在新页面标题**、**Tab 键焦点有可见轮廓**。改动导航、布局或图表后应先跑这一项。
  有效字号 = SVG `font-size` × (渲染宽度 / viewBox 宽度)；这一指标曾查出证据森林与跨波森林图在手机上只有 4px 的问题。
- **推送**：若 `github.com` 不可达，用 `git -c http.curloptResolve=github.com:443:<可用IP> push`；先 `ls-remote` 逐个试 IP。
