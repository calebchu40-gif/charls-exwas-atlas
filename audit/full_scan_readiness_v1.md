## 2. 未完成（阻塞项）

### P0-1 全量变量注册表（最大缺口）

- 现状：只有**模板**；没有覆盖 5 波约 2,000+ 个变量的注册表。
- 需要：每个变量一条 `VariableSpec`，含
  `concept_id / role / label / wave / variable / kind(continuous|binary|categorical) /
   unit / transform(log10|z|none) / valid_min / valid_max / levels / reference / family(gaussian|binomial|ordinal)`。
- 工作量：自动从 `catalog.json` 生成草稿（约 1 天）+ 人工复核分类与参照组（3–5 天）。

### P0-2 协变量谐调（每波命名不同）

| 教育 | 2011 `bd001`；2013 `zbd001`/`bd001_w2_4`；2015/2018 `bd001_w2_4`；2020 `ba010` | 需统一为 4 类（小学以下/小学/初中/高中以上）并写映射 |

### P1-1 每波 DesignSpec

- 现状：只有模板与 2011 pilot 草案；2013/2015/2018/2020 未写。
- 需要：权重、PSU、协变量集（M0/M1/M2）、是否 scale_outcome、方差限制说明。
- 工作量：1 天。

### P1-2 全量 runner 配置

- 需要：按"波次 × 结局域"切片、断点续跑、每片 manifest（代码/配置/数据哈希）、失败记录。
- 现状：`run_exwas_scan.py` 可跑单批，未配置全量切片。
- 工作量：1–2 天。

### P1-3 披露流程嵌入

- 官方要求：公开发布前，每条 `analysis_id` 必须有披露决定（`approved_public_aggregate` / `withheld`）。
- 现状：契约与模板已有；扫描产出尚未接入。
- 工作量：1 天。

### P1-4 线程预算（按你的服务器限制）

- 实测引擎 13–20 ms/模型；**8–16 线程足够**：
  - 27.3 万对 ÷ 16 线程 × 20 ms ≈ **5.7 分钟**
  - 含 3 套模型 ≈ **17 分钟**
- 结论：线程不是瓶颈，按 **8** 或 **16** 配置即可，不必开大。

## 5. 为什么"可用"只有目录的一半左右

| 原因 | 例子 |
|---|---|
| **并集 vs 单波** | 1,319 是五波并集；2011 只有 686 个暴露概念 |
| **字段 vs 概念** | 2011：1,789 个字段 → 686 个概念（2.6 字段/概念）；2018：1,741 → 501（3.5） |
| **多题项合并** | 一个"高血压"概念含"是否知道/是否诊断/诊断年份"3 个字段 |
| **筛选** | 排除 `DO NOT ANALYZE`、诊断年份类元数据、无单位且无标签、无序多分类 |
| **2020 短问卷** | 2020 只有 307 个字段、208 个暴露概念 |

**结论**：约一半是"去重 + 筛选"的正常结果，不是数据丢失。
