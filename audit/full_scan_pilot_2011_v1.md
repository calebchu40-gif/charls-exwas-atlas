# 2011 核心集 Pilot v1（已跑通）

日期：2026-11-02
状态：管线端到端跑通；注册表需数据驱动清洗后重跑。

---

## 1. 本次配置

| 项 | 值 |
|---|---|
| 波次 | 2011 |
| 暴露 | 434 个连续变量（有单位、在分析表中存在） |
| 结局 | 16 个血检指标（biochemistry） |
| 模型 | M0（年龄、性别）、M1（+教育、城乡） |
| 权重 / PSU | `bloodweight` / `communityID` |
| 引擎 | `exwas_engine.scan`，单进程 |
| 输出 | `private/results/pilot_2011_core_continuous_v1.csv`（13,888 行） |

## 2. 结果

| 指标 | 数值 |
|---|---|
| 拟合总数 | 13,888（434 × 16 × 2） |
| 成功 | **8,736（63%）** |
| 暴露零方差 | 2,300 |
| 无合格记录 | 1,230 |
| PSU 不足 | 888 |
| 数值不可用 | 732 |
| 结局零方差 | 2 |
| 耗时 | **453.7 秒**（约 33 ms/次拟合） |

结论：管线正确、速度符合预期；**63% 可估率偏低**，原因是注册表把大量非数值/常量字段当成连续变量。

## 3. 需要修正

1. **数据驱动过滤**：注册表生成时统计每个候选变量的
   - 数值化比例（≥90%）
   - 非缺失数（≥500）
   - 血液子样本内标准差 > 0
2. **区分零方差来源**：常量、全缺失、纯文本，分别记录
3. `numerically_unavailable` 的具体引擎报错需落到 `engine_warnings` 并汇总
4. 跑完 2011 后与现有 950 条中对同一血检结局的结果做方向/量级对照

- 重跑 2011 pilot（预计 4–6 分钟）

## 5. v2 更新（数据驱动注册表）

按"分析样本内数值化比例、非缺失数、加权 SD"过滤后：

| 指标 | v1 | v2 |
|---|---|---|
| 暴露 | 434 | 38 |
| 结局 | 16 | 15 |
| 拟合数 | 13,888 | 1,140 |
| 成功 | 8,736（63%） | **1,140（100%）** |
| 耗时 | 454 s | 27.5 s |

结论：数据驱动过滤把可估率从 63% 提到 100%，但暴露数骤降——说明大量问卷条目是
**条件题/稀疏题**（如仅部分人回答），不适合当连续暴露。下一步重点转向
**分类/二分类暴露**（燃料、水源、行为、社会经济），这才是核心集的主体。

## 6. v3：连续 + 二分类 + 分类（2011）

注册表按"核心域 + 覆盖度 ≥50% + 每水平 ≥30 例"重建，并加入二分类诊断结局：

| 类型 | 暴露 | 结局 |
|---|---|---|
| 连续 | 48 | 23 |
| 二分类 | 24 | 23 |
| 分类（多水平） | 15 | 35 |

| 指标 | 数值 |
|---|---|
| 拟合行数 | 20,088 |
| 成功 | **19,798（98.6%）** |
| 数值不可用 | 290（稀有水平 × 稀有结局的完全分离） |
| 唯一配对 | 6,981 |
| p<0.05 比例 | 27.6%（未校正，预期偏高） |
| 耗时 | 603 秒（约 30 ms/次拟合） |

结论：混合类型管线跑通；剩余 1.4% 失败是统计上的分离问题，需在注册表层加"每水平最少事件数"规则。

## 7. 与现有 950 条对账的发现

- 950 条中 2011 年有 345 行，其中 240 行与 pilot 的表型变量重叠；
- 但**暴露概念命名不同**：发布结果用"水平级概念"（如 `cooking_fuel_LPG`），
  pilot 用"变量级概念 + 多水平项"（如 `cooking_fuel_main` 的 level 2/5/6）；
- 因此对账需要一张**概念-水平映射表**，不能直接按变量名 join。

下一步：先建映射表，再比较方向与显著性一致率。
