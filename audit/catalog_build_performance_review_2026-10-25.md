# 目录生成器性能复核（2026-10-25）

## 变更

`build_charls_atlas_catalog.py` 在处理大量已存在字段时，原先每条概念 crosswalk 都扫描完整输出列表；并在新增审计来源行时逐行筛选原始变量表查找来源文件。现改为先建立 `(wave, variable)` 的来源索引，并对目录输出行建立同键索引，重复匹配只访问同一波次字段的少量记录。

## 结果等价核验

分别在优化前与优化后直接运行主目录生成器；`charls_atlas_candidate_fields_v0.csv/.json`、`charls_atlas_candidate_series_v0.csv/.json` 和网站主目录 `catalog.json` 五个文件的 SHA-256 完全一致。直接运行优化后生成器约 40.9 秒；优化前完成第一次索引改造后的单次运行约 44.0 秒，单次墙钟样本易受机器负载影响。

Python `cProfile` 同机采样由 74.1 秒、102.4 百万次调用降至 57.3 秒、55.7 百万次调用（约减少23%采样耗时和46%调用数）。这包括生成器启动的角色覆盖子进程，也受性能分析器开销影响，不能视作固定的生产耗时或服务器性能承诺。全量终结构建仍须按审计依赖顺序运行，不能因部分输出暂时一致而跳过必要的交叉表与状态传播步骤。
